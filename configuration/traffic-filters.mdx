Traffic filters control which visitors' data gets processed and sent to your ad platforms. Filter out bots, irrelevant geographies, and specific IP addresses to keep your conversion data clean.

## Accessing Traffic Filters

1. Go to **Configuration** in the sidebar
2. Select your domain
3. Click the **Filters** tab

## Plan Availability

Bot detection and country filtering run on every plan. Bot detection needs no configuration.

| Feature | Signal | Clarity |
|---|---|---|
| Bot score threshold (no effect today) | Yes | Yes |
| Custom user-agent patterns | Yes | Yes |
| Market (metro-area) narrowing | Yes | Yes |
| IP filtering | Yes | Yes |

A control your plan does not include shows an upgrade card in its place.

## Bot Filtering

Bot detection runs on every plan and needs no configuration, so the Bot Filtering section carries an **Always On** badge. It blocks known bots, crawlers, and automated traffic from being counted as conversions. Signal+ adds custom user-agent patterns on top, plus a bot score threshold that has no effect today.

### Basic Bot Filtering

- **Known bot blocking:** Automatically filters traffic from recognized bots and crawlers, such as Bingbot, using a maintained list of known bot user-agent patterns. Google's crawler and ad-review user agents, such as Googlebot and AdsBot-Google, skip this list and every other filter, because blocking them can get your ads disapproved. The one exception: a conversion they send to `/__cc/conv` is dropped and never counted.
- This runs silently, no configuration needed

### Advanced Bot Filtering (Signal+)

- **Bot score threshold:** CleanClicks does not receive Cloudflare bot scores today, so this setting has no effect yet. Where Cloudflare gives a request a bot score, a *lower* score means the request is more likely a bot, and CleanClicks blocks a tracking request whose score falls **below** your threshold, so a **higher** threshold blocks more. A request without a score is not checked. Set a value from 0 to 99; 0 turns this filter off. On Signal+ plans, CleanClicks sets the threshold to 30 during setup if it is 0; that value has no effect today either.
- **Custom blocked UA patterns:** Add your own user-agent patterns to block. Useful for filtering proprietary crawlers or monitoring tools that your analytics shouldn't count.

### Adding Custom UA Patterns

1. In the Bot Filtering section, find **Custom Blocked User Agents**
2. Enter a pattern (e.g., `SemrushBot` or `AhrefsBot`)
3. Click **Add**
4. Save your configuration

Patterns are matched against the visitor's user-agent string. Partial matches work: `Semrush` will match `SemrushBot/7.0`.

## Geographic Filtering

**By default, CleanClicks filters to US visitors only.** A US-only geo allowlist is applied on every plan whenever you haven't configured geo yourself. To accept traffic from other countries (or turn geo filtering off), edit the country list below -- country-level geo customization is available on every plan. Filter traffic based on the visitor's country:

### How It Works

You choose a mode and a list of countries:

- **Allowlist mode:** Only visitors from the listed countries are processed. Everyone else is filtered out.
- **Blocklist mode:** Visitors from the listed countries are filtered out. Everyone else is processed.

### Setting Up Geo Filtering

1. Enable **Geo Filtering** toggle
2. Choose **Allowlist** or **Blocklist** mode
3. Add countries using their two-letter country codes (e.g., `US`, `CA`, `GB`, `AU`)
4. Save

### Markets (US metro areas), Signal+

Signal and Clarity can narrow an allowlist to the US metro areas you actually serve. The **Markets (US metro areas)** picker appears only in **Allowlist** mode, and markets narrow within the countries you already allow. Leave it empty to track your whole country list. Visitors whose metro area cannot be determined are always tracked, never blocked.

### Common Configurations

- **US-only business:** Allowlist with `US`
- **North America:** Allowlist with `US`, `CA`
- **Block known bot-farm countries:** Blocklist mode with specific countries

Geographic filtering happens before conversion processing, so filtered traffic doesn't count toward your session limit or get sent to ad platforms.

## IP Filtering

Available on **Signal** plans and above. Filter exact IP addresses; ranges are not supported.

### Modes

- **Blocklist:** Block specific IPs (e.g., your office IP to exclude internal traffic)
- **Allowlist:** Only allow specific IPs (rare, but useful for testing)

### Adding IPs

1. Enable **IP Filtering** toggle
2. Choose **Blocklist** or **Allowlist** mode
3. Enter one IP address and click **Add** (or press Enter); repeat for each address
4. Save

Supports individual IPs (e.g., `203.0.113.50`). Useful for filtering your own office traffic, known spam sources, or competitor IPs.

## Allowed Origins

The **Allowed Origins** list controls which website origins get a CORS response header from your CleanClicks subdomain. It also controls which websites can send a visitor's request to allow sale or sharing again. Those requests go to `/__cc/optin` and `/__cc/optin-confirm`, and both refuse a request from any website not on the list, returning a 403 error. Pages on your CleanClicks subdomain itself are always accepted. No other request is refused because of this list.

- With an empty list, the header goes to `https://yourdomain.com` and `https://www.yourdomain.com`.
- Adding any origin replaces that default pair. To keep your own domain, add `https://yourdomain.com` and `https://www.yourdomain.com` along with the new origin, such as `https://app.yourdomain.com`.
- Enter each origin with `https://` at the start.

The tracking endpoints that receive conversions and events do not use this list and accept requests from any origin, so embedded pages such as Shopify's Custom Pixel sandbox can send data. Requests to `/__cc/conv` and `/__cc/identify` are checked another way: each must name your domain in its body, and that domain must match the CleanClicks subdomain the request was sent to (`cleanclicks.yourdomain.com`). A request that names a different domain is refused.

## How Filters Stack

Filters are applied in order. A request must pass all active filters to be processed:

1. **Bot filter** — known-bot and non-browser user agents are blocked first.
2. **IP filter** — if you've set an IP allowlist/blocklist, it's checked next.
3. **Geo filter** — the visitor's country is checked against your allowlist/blocklist (US-only by default).

Traffic that's filtered out is not counted toward your session limit, not sent to ad platforms, and doesn't appear in your conversion data. Filtered requests are still logged in traffic analytics (on Signal+ plans) so you can see what's being blocked.
