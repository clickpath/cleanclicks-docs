The Vendors tab in Configuration controls which ad and analytics platforms receive your conversion data. Each vendor can be enabled or disabled independently, and most require platform-specific credentials.

## Accessing Vendor Configuration

1. Go to **Configuration** in the sidebar
2. Select the domain from the domain picker (if you have multiple)
3. Click the **Vendors** tab

## Supported Vendors

### Ad Platforms

These count against your plan's ad platform limit.

| Vendor | What It Does | Required Fields |
|---|---|---|
| **Google Ads** | Uploads offline conversions via the Google Ads API (requires a click ID -- see note) | Customer ID, Conversion Action resource name |
| **Meta (Facebook)** | Sends events via Meta Conversions API (CAPI) | Pixel ID, Access Token |
| **TikTok** | Sends events via TikTok Events API | Pixel Code, Access Token |
| **Microsoft Ads** | Uploads offline conversions via Microsoft Ads | Customer ID, Account ID |

### Analytics Platforms

| Analytics connection | Fields shown in manual configuration |
|---|---|
| **GA4** | Measurement ID, API Secret |
| **Usermaven** | API Key, Tracking Host |

Use the fields shown for the selected domain and supported connection path. The Usermaven server-side relay also requires an API Key and Server Token in its domain configuration; Tracking Host does not replace that token. If the needed credential is not exposed in your screen, ask support to verify the server-side configuration. Enabling a proxy alone does not configure server-side delivery.

GA4 and Usermaven are included in the current Signal and Clarity analytics layer and do not use an ad-destination slot.

## Enabling a Vendor

1. Find the vendor card on the Vendors tab
2. Toggle the vendor **on**
3. Fill in the required fields
4. Click **Save**

Sensitive fields (access tokens, API secrets) are masked after saving. You'll see `••••••••` instead of the actual value. To update a token, enter a new value and save again.

## Platform Limits

| Current plan | Current ad-destination allowance |
|---|---:|
| Signal | Any 3 of Google Ads, Meta, TikTok, and Microsoft Ads |
| Clarity | All 4 current ad destinations |

GA4 and Usermaven are analytics connections and do not use an ad-destination slot. LinkedIn support exists in the product but is not part of the current sellable destination set. Do not configure or promise it for a new buyer until the offer decision is accepted.

## Disabling a Vendor

Toggle a vendor **off** to stop sending it data. The credentials are retained, so you can re-enable later without re-entering them.

## Vendor-Specific Notes

### Google Ads
- **Customer ID** is the 10-digit Google Ads account number
- **Conversion Action resource name** is the API resource path for the conversion (format: `customers/1234567890/conversionActions/123456789`), not the `AW-xxx/yyy` gtag snippet ID
- Click conversions require a click ID (`gclid`, `wbraid`, or `gbraid`); conversions without one are recorded in CleanClicks but not uploaded to Google Ads
- The Developer Token is managed by CleanClicks; you don't need to provide one

### Meta (Facebook)
- Use a **System User Access Token**, not a personal access token. Generate it in Meta Business Manager > Business Settings > System Users.
- The token needs `ads_management` and `ads_read` permissions
- Optionally set a **Test Event Code** to verify events in Meta's Events Manager before going live

### TikTok
- Get your **Access Token** from TikTok Events Manager > Settings > Generate Access Token
- The **Pixel Code** is on the same page (format: `CXXXXXXXXXXXXXXXXX`)

### Microsoft Ads
- Requires your **Customer ID** and **Account ID** from the Microsoft Ads dashboard
- Both are visible in the top-right of your Microsoft Ads interface

### GA4
- **Measurement ID** is in `G-XXXXXXXXXX` format (found in GA4 Admin > Data Streams)
- **API Secret** is generated in GA4 Admin > Data Streams > your stream > Measurement Protocol API secrets

### Usermaven
- Manual vendor configuration shows **API Key** and **Tracking Host**. The server-side relay separately requires a **Server Token**. Verify the intended workspace and complete credential configuration before testing delivery. Do not paste a token into the Tracking Host field.
