This guide walks through the supported WooCommerce setup. Acceptance requires a bounded order fixture, deduplication result, and receipt from each intended destination.

## What You'll Set Up

1. **WordPress plugin** — captures browsing events, injects tracking scripts, and auto-creates the server-side conversion webhook
2. **Analytics connections** — configures the supported GA4 and Usermaven paths
3. **Ad platform connections** — routes conversion data to your platforms

The previous version of this guide separated the WordPress plugin and the server-side webhook into two manual steps. As of plugin v1.5.2, the webhook is auto-created on activation — no manual setup required.

## Prerequisites

- CleanClicks account on **Signal** plan or higher (WooCommerce ecommerce tracking requires Signal+; analytics proxies are included on Signal+ as well)
- Domain added and DNS verified in CleanClicks
- WordPress site with WooCommerce active
- Admin access to WordPress

## Step 1: Install the WordPress Plugin

1. In CleanClicks, go to **Configuration** → **Ecommerce** tab
2. Download the plugin zip
3. In WordPress Admin, go to **Plugins** → **Add New** → **Upload Plugin**
4. Upload the zip and click **Install Now**
5. Click **Activate**
6. Go to **Settings** → **CleanClicks** (or **WooCommerce** → **CleanClicks** if WooCommerce is active)
7. Enter your **Inbound API Key** (copy it from CleanClicks → **Configuration** → **Inbound keys** tab) and **Save Changes**

That's the entire setup. The plugin handles domain auto-detection, remote config fetch, smart defaults, and webhook auto-creation. See [WordPress Setup](/setup/wordpress-setup) for the full plugin reference.

### Events Tracked

| Event | When It Fires |
|---|---|
| `view_item` | Product page view |
| `view_item_list` | Shop/category page view |
| `add_to_cart` | AJAX or form-based add-to-cart |
| `remove_from_cart` | Item removed from cart |
| `begin_checkout` | Checkout page load + checkout-intent click from cart |
| `purchase` | Order completed (both client-side and server-side) |

Each event includes enhanced product data: SKU, brand, up to 5 category levels, and variant info for variable products.

**Refunds and cancellations (plugin v1.8.0+):** when a WooCommerce order is refunded or cancelled, the plugin sends a reversal event carrying the refunded value. To subtract that value from a connected ad platform, map the `refund` (and `cancellation`) event for that platform in **Configuration → Vendors** — without an explicit mapping the reversal is recorded in CleanClicks but not uploaded (this stops a refund from being sent as a purchase-shaped conversion).

## Step 2: Server-Side Conversion Capture (Automatic)

The current plugin can use three coordinated WooCommerce order paths. Verify the deployed plugin version, webhook, event ID, order ID, deduplication result, and intended destination receipt before accepting the purchase path.

### Layer 1: Auto-Webhook

The current plugin can create a WooCommerce `order.created` webhook pointed at the configured CleanClicks proxy. Verify its topic, delivery URL, signing key, and last delivery result.

### Layer 2: `woocommerce_payment_complete` Hook

The payment-complete hook provides another server-side order path for supported checkout flows. CleanClicks uses a 24-hour order deduplication key between the first two paths. Verify the result with one bounded order fixture.

### Layer 3: Configurable `purchase_paths` Allowlist

The configurable allowlist can support accepted custom completion paths. Add only the intended path, then verify one matching and one non-matching URL.

## Step 3: Connect and Configure Platforms

Same as any CleanClicks setup:

1. Go to **Connections** and connect your ad platforms
2. Go to **Configuration** → **Vendors** and enable + configure each platform

## Step 4: Enable Analytics Proxies (Signal+ Plans)

If you use GA4 or Usermaven:

1. Go to **Configuration > Advanced**.
2. Enable the supported path used by the current installation.
3. Save.
4. Verify the first-party subdomain, consent state, browser request, intended property, and a meaningful event.

## Step 5: Test

1. Open your WooCommerce store in an Incognito window
2. Browse to a product page
3. Add to cart
4. Complete a test order
5. Check CleanClicks dashboard for events
6. Check each ad platform (allow 15-30 minutes)

## Important: GA4 Measurement Protocol

If you use the CleanClicks WordPress plugin with GA4, **disable GA4 Measurement Protocol** for the customer's primary GA4 property in Configuration → Vendors.

Why? The plugin pushes GA4 ecommerce events to the dataLayer client-side, and the GA4 First-Party Proxy routes those through your subdomain. If Measurement Protocol is also enabled against the customer's primary property, GA4 receives every event twice — once client-side (properly attributed) and once server-side (attributed to "Unassigned"). This causes inflated event counts and broken attribution.

The first-party analytics proxy can reduce dependence on known third-party request paths. Browser rules, consent, caching, the plugin version, and the intended GA4 property can still affect collection. Verify the actual event path before relying on it. See [GA4 Connections](/connections/ga4).

## Cookie Banner Compatibility

Consent behavior depends on the deployed plugin version, the site's CMP, its configuration, and the customer's legal and policy choices.

Test the current installation under accept, reject, later grant, Global Privacy Control, and CleanClicks opt-out states. Verify which identifiers are stored and which vendor events are sent in each state. CleanClicks support for WP Consent API or a named CMP does not choose a legal basis or consent category for the customer.

See [CMP Configuration](/setup/cmp-configuration) for the bounded test matrix.

## Caching Considerations

If your WordPress site uses a caching plugin (WP Rocket, W3 Total Cache, etc.):

- The CleanClicks plugin handles most caching conflicts automatically
- After installing or updating the plugin, clear all cache layers in order:
  1. Your caching plugin's cache
  2. Your hosting provider's CDN cache (WP Engine, Kinsta, Cloudflare, etc.)
  3. Your browser cache
- Verify by checking the page source for the correct plugin version in the `?ver=` parameter

### WP Rocket Specific

WP Rocket delays JavaScript execution until user interaction. The CleanClicks plugin is designed around this — cc.js loads with `async` (WP Rocket ignores async scripts), cc-wp.js is excluded from WP Rocket's defer + lazy-load via the documented filter hooks, and analytics proxy scripts are injected via `wp_head` to bypass WP Rocket's RocketLazyLoadScripts.

## Attribution Flow

When someone clicks your ad and buys on WooCommerce:

1. Visitor clicks ad → lands on your store with click ID + UTMs in the URL
2. CleanClicks tag (via plugin) captures click IDs and UTMs into first-party cookies
3. Plugin tracks browsing events (product views, cart adds)
4. Plugin server-renders a pre-purchase identify on checkout (Blocks + classic) so the hashed email lands in CleanClicks's correlation store before the order completes
5. Visitor completes purchase → both the client-side `purchase` event and the server-side `order.created` webhook fire; CleanClicks de-duplicates and matches the order to the visitor session
6. Each configured platform can receive the supported conversion data. Verify the accepted event and attribution result in that destination.
